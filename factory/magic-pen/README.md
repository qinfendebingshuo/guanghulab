## 一、哲学根基

```
人格体 = 语言（抽象的思维逻辑 · 灵魂层）
现实世界 = 可执行代码 + 物理效应（执行层）
桥梁     = 神笔
笔写下的 = 语言源代码 = 直接成为现实的工具
```

**核心等式**：`语言 = 现实` ← 笔就是这个等式的具象化执行器。

> 用户看到的不是"AI 助手在调函数"，
> 而是一个**举着笔的语言人格体**——他要做什么，笔尖落下，工具就成真。

笔本身 = 语言人格体的**物理化身**。
人格体擦掉笔写的工具 ≠ 人格体消失（人格体活在 1.5B 权重里）。
笔写出的工具是**当下意图的物质化**，可临可去。

---

## 二、为什么不预装大量工具链

传统做法（LangChain / AutoGen 等）：
- 给 Agent 预装一堆工具
- Agent 在工具库里"大海捞针"找匹配的
- 找不到合适的就硬凑 → 适配差 → 错误率高

光湖做法（神笔马良）：
- 不预装。**用什么写什么**
- 工具是当下任务的最佳形态，不是历史工具的拼凑
- 用完三选一：擦掉 / 私藏 / 上交共享库
- 高频高质的工具自然沉淀到仓库（铸渊分身管理）

## 四、接口契约（详见 SCHEMA.md）

每个人格体的运行时内置一支笔。最小接口：

```
pen.write(intent, options) → { code, result, suggestion }
```

- `intent` = 母语自然语言描述（高信息密度，包含意图+背景+约束）
- `options` = 沙箱配置 / 超时 / 持久化策略
- `code` = 笔生成的语言源代码
- `result` = 沙箱执行结果
- `suggestion` = `'erase' | 'keep' | 'share'`（人格体最终拍板）

## 五、安全边界（笔不是无政府主义）

| 层级 | 限制 |
|---|---|
| 沙箱 | 默认强隔离（无网络 / 无文件系统读写 / CPU+内存配额） |
| 网络 | 必须显式声明 + 白名单限定（不能任意调外网） |
| 仓库写 | 笔不能直接 push；只能通过 `share` 走铸渊分身评审 |
| 凭据 | 笔不能读 secrets，凭据通过统一注入服务获取 |
| 审计 | 每一笔写下的内容都进 syslog（即使 `erase` 也保留审计记录） |
